# Phase 4: ソース横断機能 詳細設計

Phase 2(daily マート)を土台に、「日付」で 3 ソースを繋ぐ機能群。
すべて独立に着手できるが、価値の高い順に (a) デイビュー → (b) 目標 → (c) AI インサイト → (d) 相関 を推奨。

## 4a. デイビュー `/day/[date]`

「この日どこへ行き、いくら使い、どう眠ったか」を 1 画面で見る。統合ホームの
「直近 7 日」の行、および Timeline の日別履歴からリンクする。

### 構成

```
/day/2026-07-04
┌───────────────────────────────────────────┐
│ 2026-07-04 (金)     [< 前日] [翌日 >]      │
│ [睡眠 6.8h 23:40-06:30] [歩数 8,200]       │
│ [活動 32min] [支出 ¥3,400]                 │
├───────────────────────────────────────────┤
│ タイムライン(既存 DayHistory + 経路マップ)  │
│ 07:10 自宅 → 08:05 移動(電車 12km)→ …    │
├───────────────────────────────────────────┤
│ この日の支出明細(家計簿の取引リスト)        │
└───────────────────────────────────────────┘
```

### 実装

- サマリ行: `marts/daily.json` の該当行
- タイムライン: 既存 `DayHistory` / `DayRouteMap` コンポーネントを流用
  (現在 Timeline ページ内にあるものを `/day/[date]` に移し、Timeline 側にはリンクを残す)
- 支出明細: 新マート `marts/budget_transactions/{YYYY-MM}.json`(月別の取引明細)を追加し、
  該当日をフロントでフィルタ
- 日付ナビ: `marts/meta.json` の範囲内で前日/翌日リンク

## 4b. 目標・予算設定

現状は「事実の表示」のみで評価軸がない。目標を持たせて各カード・チャートに意味を与える。

### 設計

- 設定はコード管理の静的ファイルで開始する(設定 UI は作らない。個人利用で変更頻度が低く、
  git 履歴に残る方が良い): `frontend/src/config/goals.ts`

```ts
export const GOALS = {
  steps_per_day: 8000,
  sleep_hours_min: 7.0,
  active_zone_min_per_week: 150,   // WHO 推奨
  budget_per_month: 200000,         // 変動費の月予算
} as const
```

- 表示:
  - StatsCard に達成率のプログレスバー(例: 歩数 8,200 / 8,000 ✓)
  - Budget の累積チャートに予算ライン(月末着地の単純外挿と比較)
  - 統合ホームの週サマリに「今週の運動 132/150 分」
- 将来設定 UI が欲しくなったら `marts/config.json`(S3)に移す

## 4c. 週次 AI インサイト(ai-agent-design.md 案 1 との接続)

設計本体は [../ai-agent-design.md](../ai-agent-design.md)。本再設計との整合のみ定義する。

- **データアクセスは Phase 2 のマートを第一級入力にする**: エージェントの `run_sql`
  (DuckDB)は生 Parquet に加えて `marts/daily.json` を読めるようにする。
  日次統合済みデータがあることで、相関の探索(睡眠×運動×支出)が 1 テーブルで済み、
  トークン消費とツール往復が減る
- 出力 `insights/YYYY-MM-DD.json` は統合ホームの「AI インサイト」カード(03 の 3e)が表示
- 実装順: mart_builder(Phase 2)→ insight_agent。同じ Docker Lambda パターン・
  同じ DuckDB 依存なので、mart_builder のイメージ構成を流用できる

## 4d. 相関ビュー `/insights`(手動探索用)

AI に任せる前に自分の目で見るための、daily マートの散布図/対比ビュー。

- 軸を選べる散布図: X/Y に daily マートの数値列(歩数・睡眠・活動・支出)を選択。
  ラグ指定(前日の X vs 当日の Y。「運動した翌日はよく眠れるか」)
- 場所タグとの対比: 特定の場所(例: ジム)に行った日/行かない日で睡眠・活動の分布を比較
  - 場所タグは `frontend/src/config/place-tags.ts` に `place_id → タグ` の手動マッピング
    (例: `{ "ChIJ...": "gym" }`)。visit データにタグを結合して集計
- 実装はすべてクライアント側(daily マートを読んで Recharts の ScatterChart)。
  新規バックエンドなし

## 4e. 通知(週次レポート配信)

- insight_agent(4c)の末尾で Slack Incoming Webhook に `summary_md` の要約を POST
  (Webhook URL は Secrets Manager `prod/dashboard/slack`)
- ダッシュボードを「見に行く」から「届く」へ。失敗しても本処理(S3 保存)には影響させない

## 優先順位と依存

| 機能 | 依存 | 工数感 |
|---|---|---|
| 4a デイビュー | Phase 2(daily + 取引明細マート) | 中(既存コンポーネント流用) |
| 4b 目標 | Phase 2(あると楽。暫定は現行データでも可) | 小 |
| 4c AI インサイト | Phase 2 + Anthropic API キー | 中(設計済み) |
| 4d 相関ビュー | Phase 2 | 中 |
| 4e 通知 | 4c | 小 |
